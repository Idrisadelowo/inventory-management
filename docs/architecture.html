Architecture overview

Factory Inventory Management System

A full-stack demo app: a Vue 3 single-page app talks over HTTP to a FastAPI service that serves in-memory data loaded from JSON files at startup. There is no database, no authentication, and no write path that persists data.

Data flow

What happens when a user changes a filter on the Dashboard.

  1. User picks a filter in FilterBarTime Period, Warehouse, Category, or Order Status.
  2. useFilters updates shared refsThe refs are declared at module level, so every component that calls useFilters() shares one state.
  3. A watcher in the view reloads datagetCurrentFilters() maps the UI names to API names (location to warehouse, period to month).
  4. api.js builds the requestAny value equal to "all" is left out, so the backend sees only active filters.
  5. FastAPI filters in memoryapply_filters() matches warehouse exactly and category/status case-insensitively; filter_by_month() matches a month like 2025-03 or expands a quarter like Q1-2025.
  6. Pydantic validates the responseTyped endpoints declare a response_model; summary, spending and reports endpoints return plain dicts.
  7. Vue recomputes derived valuesRaw responses land in refs (allOrders, inventoryItems); charts, totals and tables are computed properties.

Data model

Mock data under server/data/, regenerated by server/generate_data.py.

Inventory · 32 items

SKU, category, warehouse, quantity on hand, reorder point, unit cost. Low stock means quantity at or below reorder point.

Orders · 250

Customer, line items, status (Delivered, Shipped, Processing, Backordered), order and delivery dates across 2025.

Demand forecasts · 9

Current versus forecast demand per SKU with a trend label.

Backlog · 4

Shortfalls per order and SKU, days delayed, priority. has_purchase_order is computed per request.

Spending + transactions · 56

Summary, monthly and category breakdowns, plus recent transactions.

Known gaps

Places where the frontend and backend don't line up, found while reading the code.

Breaks at runtime

Tasks endpoints don't exist

App.vue calls getTasks, createTask, deleteTask and toggleTask, which hit /api/tasks. The backend has no such route, so these return 404.

Breaks at runtime

Purchase orders are half-built

Dashboard.vue renders <PurchaseOrderModal> but never imports or registers it, and no such component file exists. /api/purchase-orders is also missing on the server, although the PurchaseOrder models are defined.

Inconsistency

Backlog view has no route

views/Backlog.vue exists but isn't registered in main.js, so it can't be reached.

Inconsistency

Reports bypasses api.js

Reports.vue hard-codes http://localhost:8001 with axios instead of going through the shared client.

Limitation

Quarters are hard-coded to 2025

QUARTER_MAP and the quarterly report only recognise 2025 dates; other years are silently skipped.

Limitation

Backlog ignores filters

total_backlog_items in the dashboard summary always counts every backlog item, whatever filters are set.
